Current State (Before)

A detailed methodology, two JSON assessment records, source registers, and validation code. Reading a rating means navigating files. Older summaries disagree with the newer records.

Proposed State (After)

A searchable directory, a shareable assessment page, and an evidence view. Every displayed outcome comes from a versioned, validated record. Research examples are visibly labeled.

01 / Directory

Find an exact route

Search asset, chain, venue, and contract. Show approval outcome, indicated grade, review date, and route completeness in every result.

02 / Assessment

Understand the outcome

Lead with a short explanation and three drivers. Expand into typed dependencies, inherited risk, local contributions, and approval blockers.

03 / Evidence

Check the reasoning

Link each material claim to inspected sources and dates. State missing evidence, its consequence, and what would close the gap. Export the frozen record.

How to earn the polished feel

Finish one real assessment page before extending the design. Use one spacing scale, quiet borders, consistent type, aligned numbers, and status labels that explain themselves. Keep evidence one interaction away.

Check the same page at 390, 768, and 1440 pixels, with long route names, missing scores, loading failures, and keyboard navigation. Ask a reader to identify the outcome, main driver, and evidence blocker in 30 seconds.

Implementation and repo caveats

Suggested production stack: Next.js, TypeScript, Tailwind, and a customized shadcn/ui component set. Initially load reviewed JSON at build time and run the Python validator in CI. Add a database when analyst editing and review history require it.

The validator needs jsonschema installed. Its default schema path and the hardening tests refer to a different directory layout; the tests also reference a conformance fixture absent from this repo. Restore that setup before using validation as a publishing gate.

Design source: Lavish's Tailwind / DaisyUI fallback, using a light corporate theme because this repository has no existing frontend or design system. This is a concept artifact, not an implemented application.
